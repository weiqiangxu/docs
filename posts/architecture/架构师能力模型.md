## 一、架构师定位

### 1.1 架构师是什么

```mermaid
flowchart TD
    A[架构师] --> B[技术专家<br/>解决复杂问题]
    A --> C[业务顾问<br/>理解业务本质]
    A --> D[团队教练<br/>提升团队水平]
    A --> E[决策者<br/>关键技术决策]
```

### 1.2 与开发的区别

| 维度 | 开发 | 架构师 |
|------|------|--------|
| 关注点 | 怎么实现 | 为什么这么做 |
| 视角 | 单个模块 | 整个系统 |
| 时间 | 当下需求 | 长期演进 |
| 沟通 | 团队内 | 跨团队/业务 |
| 决策 | 技术细节 | 技术方向 |

## 六、成长路径

### 6.1 职级阶梯

```mermaid
flowchart LR
    A[初级开发] --> B[中级开发]
    B --> C[高级开发]
    C --> D[技术专家]
    D --> E[架构师]
    E --> F[资深架构师]
    F --> G[首席架构师/CTO]
```

### 6.2 各阶段重点

| 阶段 | 重点 | 周期 |
|------|------|------|
| 初级 | 实现功能、学习规范 | 1-2 年 |
| 中级 | 独立负责模块 | 2-4 年 |
| 高级 | 解决复杂问题、影响团队 | 4-7 年 |
| 专家 | 精通某领域、跨团队影响 | 7-10 年 |
| 架构师 | 系统设计、技术决策 | 10+ 年 |

### 6.3 关键转折点

    B --> C[转折点3<br/>从技术到业务]
    C --> D[转折点4<br/>从个人到团队]

### 7.5 思维训练

- **第一性原理**：从本质出发思考
- **系统性思维**：看整体而非局部
- **长期思维**：考虑未来演进
- **权衡思维**：没有银弹，只有取舍
- **批判性思维**：质疑权威，独立判断

## 八、架构师的反模式

### 8.1 避免成为

```mermaid
flowchart TD
    A[架构师反模式] --> B[象牙塔架构师<br/>脱离一线]
    A --> C[简历驱动架构师<br/>为简历选型]
    A --> D[Ctrl+C 架构师<br/>照搬大厂方案]
    A --> E[全能架构师<br/>事必躬亲]
    A --> F[空头架构师<br/>只画图不落地]
```

### 8.2 常见误区

| 误区 | 正确做法 |
|------|---------|
| 过度设计 | 满足当下+6个月演进 |
| 技术至上 | 业务驱动技术 |
| 一次性完美 | 持续演进 |
| 自己写 | 优先用成熟方案 |
| 不写代码 | 保持编码 |
