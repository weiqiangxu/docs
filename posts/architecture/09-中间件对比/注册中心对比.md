## 一、注册中心职责

```mermaid
flowchart TD
    A[注册中心] --> B[服务注册<br/>服务启动时登记]
    A --> C[服务发现<br/>调用方查询可用实例]
    A --> D[健康检查<br/>剔除故障实例]
    A --> E[元数据管理<br/>版本、权重等]
```

### 工作流程

```mermaid
sequenceDiagram
    participant P as Provider
    participant R as Registry
    participant C as Consumer

    P->>R: 注册服务（IP:Port）
    C->>R: 订阅服务
    R-->>C: 推送实例列表
    P->>R: 心跳保活
    R->>C: 通知实例变更
```

## 二、四大注册中心概览

| 注册中心 | 出身 | 语言 | 一致性 | 适用 |
|---------|------|------|--------|------|
| **ZooKeeper** | Yahoo 2008 | Java | CP | 强一致场景 |
| **Eureka** | Netflix 2012 | Java | AP | Spring Cloud |
| **Consul** | HashiCorp 2014 | Go | CP | 多语言 |
| **Nacos** | 阿里 2018 | Java | AP/CP | 阿里/Spring Cloud |

## 三、CAP 模型对比

### 3.1 CAP 选择

```mermaid
flowchart TD
    A[CAP 选择] --> B[CP<br/>强一致]
    A --> C[AP<br/>高可用]
    Note over B: ZK/Consul/Nacos(CP模式)
    Note over C: Eureka/Nacos(AP模式)
```

### 3.2 不同选择的影响

#### CP（强一致）

```mermaid
sequenceDiagram
    participant C as Client
    participant L as Leader
    participant F1 as Follower1
    participant F2 as Follower2

    Note over L,F2: F2 网络分区
    C->>L: 写入
    L->>F1: 同步
    L->>F2: 同步失败
    Note over L: 等待多数派确认
    L-->>C: 写入成功
    Note over F2: F2 不可用
```

特点：
- 写入需多数派确认
- 分区时少数派不可用
- 数据强一致

#### AP（高可用）

```mermaid
sequenceDiagram
    participant C as Client
    participant N1 as Node1
    participant N2 as Node2

    Note over N1,N2: 网络分区
    C->>N1: 写入 A=1
    N1-->>C: 成功
    C->>N2: 读取
    N2-->>C: 返回旧值 A=0
    Note over N1,N2: 分区恢复后同步
```

特点：
- 任一节点可读写
- 分区时仍可用
- 数据可能短暂不一致

### 3.3 为什么注册中心选 AP

```mermaid
flowchart TD
    A[注册中心选 AP] --> B[可用性 > 一致性]
    A --> C[服务列表短暂不一致可接受]
    A --> D[避免注册中心故障拖垮业务]
    A --> E[客户端容错能力强]
```

## 四、架构对比

### 4.1 ZooKeeper

```mermaid
flowchart TD
    L[Leader] --> F1[Follower]
    L --> F2[Follower]
    L --> F3[Observer]
    Note over L,F3: ZAB 协议
```

特点：
- 树形数据结构（ZNode）
- 临时节点表示存活
- Watcher 通知机制
- 复杂的 Leader 选举

### 4.2 Eureka

```mermaid
flowchart LR
    S1[Server1] -.->|复制| S2[Server2]
    S2 -.->|复制| S3[Server3]
    S1 --> P[Provider]
    S1 --> C[Consumer]
```

特点：
- Peer-to-Peer 复制
- 无主从
- 心跳续约
- 自我保护模式

### 4.3 Consul

```mermaid
flowchart TD
    S[Server] --> A1[Agent]
    S --> A2[Agent]
    A1 --> S1[Service1]
    A2 --> S2[Service2]
    S --> S2
```

特点：
- Agent 部署在每个节点
- Gossip 协议通信
- Raft 一致性
- 支持 KV 存储

### 4.4 Nacos

```mermaid
flowchart TD
    C[Client] --> N1[Nacos Server1]
    C --> N2[Nacos Server2]
    N1 -.->|集群同步| N2
    N1 --> DB[(MySQL)]
    N2 --> DB
```

特点：
- 支持注册中心+配置中心
- AP/CP 切换
- 长连接推送
- 控制台管理

## 五、功能特性对比

### 5.1 综合对比

| 特性 | ZooKeeper | Eureka | Consul | Nacos |
|------|-----------|--------|--------|-------|
| **CAP** | CP | AP | CP | AP/CP |
| **健康检查** | Session | 心跳 | TCP/HTTP/脚本 | TCP/HTTP |
| **多数据中心** | 弱 | 不支持 | 支持 | 支持 |
| **配置中心** | 可作 | 否 | 是 | 是 |
| **管理控制台** | 第三方 | 简单 | 有 | 有 |
| **多语言** | SDK | HTTP | HTTP/DNS | HTTP/DNS |
| **服务网格** | 否 | 否 | Connect | 是 |

### 5.2 健康检查

| 注册中心 | 检查方式 |
|---------|---------|
| ZooKeeper | Session 心跳 |
| Eureka | 客户端心跳 30s |
| Consul | TCP/HTTP/Script |
| Nacos | TCP/HTTP/心跳 |

### 5.3 服务发现方式

```mermaid
flowchart TD
    A[发现方式] --> B[客户端拉取<br/>Eureka/Nacos]
    A --> C[服务端推送<br/>Nacos/ZK Watcher]
    A --> D[DNS<br/>Consul]
```

| 注册中心 | 方式 | 实时性 |
|---------|------|--------|
| ZooKeeper | Watcher 推送 | 高 |
| Eureka | 客户端定时拉取 | 30s 延迟 |
| Consul | 长轮询 | 中 |
| Nacos | 长连接推送 | 高 |

### 5.4 配置中心

| 注册中心 | 配置能力 |
|---------|---------|
| ZooKeeper | 可作但弱 |
| Eureka | 不支持 |
| Consul | KV 存储 |
| Nacos | 专业配置中心 |

## 七、选型建议

### 7.1 决策树

```mermaid
flowchart TD
    A[选型] --> B{需要配置中心?}
    B -->|是| C[Nacos]
    B -->|否| D{技术栈}
    D -->|Java/Spring Cloud| E{版本}
    D -->|多语言| F[Consul]
    E -->|老版本| G[Eureka]
    E -->|新版本| H[Nacos]
    D -->|强一致需求| I[ZooKeeper]
```

### 7.2 场景推荐

| 场景 | 推荐 | 原因 |
|------|------|------|
| Spring Cloud Alibaba | Nacos | 原生集成 |
| Spring Cloud Netflix | Eureka | 兼容（已维护模式） |
| 多语言微服务 | Consul | HTTP/DNS |
| 强一致要求 | ZooKeeper | CP 模型 |
| 服务网格 | Nacos/Consul | 集成能力 |
| 阿里技术栈 | Nacos | 阿里出品 |

### 7.3 Eureka 2.0 停止开发

```mermaid
flowchart LR
    A[Eureka 2.0] -->|2018 停止| B[维护模式]
    B --> C[新项目不推荐]
    C --> D[推荐迁移 Nacos/Consul]
```

### 7.4 Nacos 优势

- 同时支持 AP/CP
- 注册中心+配置中心一体
- 长连接推送，实时性高
- 阿里大规模生产验证
- 友好的管理控制台

## 八、自我保护机制

### 8.1 Eureka 自我保护

```mermaid
flowchart TD
    A[15分钟内心跳<85%] --> B[进入自我保护]
    B --> C[不再剔除实例]
    Note over C: 防止网络分区误剔除
    A --> D[网络恢复]
    D --> E[退出自我保护]
```

### 8.2 Nacos 自我保护

- 临时实例：心跳低于阈值不剔除
- 持久化实例：主动探测

### 8.3 ZooKeeper Session

```
Session 超时 → 临时节点删除
网络抖动 → 误删除风险
```
