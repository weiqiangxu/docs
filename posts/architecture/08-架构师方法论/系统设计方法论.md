## 三、ADD 方法

Architecture-Driven Design，基于属性的设计方法：

```mermaid
flowchart TD
    A[输入<br/>需求/约束/驱动] --> B[分解系统]
    B --> C[选择架构模式]
    C --> D[分配功能]
    D --> E[定义接口]
    E --> F[验证质量属性]
    F -->|满足| G[输出]
    F -->|不满足| B
```

### 3.1 步骤

| 步骤 | 说明 |
|------|------|
| 1. 确定驱动因素 | 性能、可用性、安全等 |
| 2. 选择架构模式 | 微服务/单体/事件驱动 |
| 3. 分配功能 | 模块划分 |
| 4. 定义接口 | 模块间通信 |
| 5. 验证质量属性 | 是否满足需求 |

## 五、设计原则

### 5.1 SOLID 原则

| 原则 | 含义 |
|------|------|
| **S** 单一职责 | 一个类一个职责 |
| **O** 开闭原则 | 扩展开放，修改关闭 |
| **L** 里氏替换 | 子类可替换父类 |
| **I** 接口隔离 | 接口最小化 |
| **D** 依赖倒置 | 依赖抽象不依赖具体 |

### 5.2 架构原则

```mermaid
flowchart TD
    A[KISS<br/>保持简单] --> B[YAGNI<br/>不要过度设计]
    B --> C[DRY<br/>不要重复]
    C --> D[SoC<br/>关注点分离]
    D --> E[POLA<br/>最小惊讶]
```

### 5.3 分布式原则

| 原则 | 说明 |
|------|------|
| Design for Failure | 假设故障必然发生 |
| Stateless | 优先无状态 |
| Idempotent | 操作幂等 |
| Async First | 优先异步 |
| Cache Everything | 能缓存则缓存 |

## 六、典型案例

### 6.1 设计一个短链系统

```mermaid
sequenceDiagram
    User->>API: 长链转短链
    API->>ID生成: 获取唯一ID
    ID生成-->>API: 1234567890
    API->>API: Base62编码 → eW6L
    API->>DB: 存储映射 eW6L → long_url
    API-->>User: 返回 https://t.co/eW6L

    User->>API: 访问 https://t.co/eW6L
    API->>Cache: 查缓存
    Cache-->>API: long_url
    API-->>User: 302 重定向
```

设计要点：
- ID 生成：雪花算法
- 编码：Base62
- 存储：MySQL + Redis 缓存
- 跳转：302 重定向
- 统计：异步上报

### 6.2 设计一个朋友圈 Feed 流

```mermaid
flowchart TD
    A[用户发动态] --> B[写自己的时间线]
    B --> C[推送到粉丝收件箱<br/>推模式]
    Note1(["大V用拉模式"])
    C -.-> Note1
    D[用户刷新] --> E[读自己收件箱]
    E --> F[聚合内容]
```

设计要点：
- 推拉结合：普通人推，大V拉
- 存储：Redis SortedSet（按时间排序）
- 优化：活跃用户才推
- 分页：游标分页

### 6.3 设计一个抢红包系统

```mermaid
sequenceDiagram
    User->>API: 发红包100元10个
    API->>DB: 创建红包记录
    API->>Redis: 预计算金额并缓存

    User2->>API: 抢红包
    API->>Redis: CAS 抢一个金额
    Redis-->>API: 8.5元
    API->>MQ: 异步入账
    API-->>User2: 抢到8.5元
```

设计要点：
- 金额预计算：发红包时拆分
- Redis CAS 抢金额
- 异步入账
- 防并发

### 6.4 设计一个 IM 系统

```mermaid
flowchart TD
    A[消息发送] --> B[网关接入]
    B --> C[消息路由<br/>查接收方连接服务器]
    C --> D[推送至接收方服务器]
    D --> E[长连接推送]
    E --> F[客户端接收]
    Note1(["离线则存消息队列"])
    D -.-> Note1
    E -.-> Note1
```

设计要点：
- 长连接：WebSocket / TCP
- 消息路由：用户→服务器映射
- 离线消息：存储 + 推送
- 消息顺序：单聊按时间，群聊按服务器时间
