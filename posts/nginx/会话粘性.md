## 一、环境准备

### 1.1 创建网络与后端服务

```bash
docker network create nginx-test

# 后端 1:Gin 服务(端口 8080)
docker run --network nginx-test -itd \
  --network-alias one \
  435861851/gin:v0.0.1

# 后端 2:echo 服务(端口 5678)
docker run --network nginx-test -itd \
  --network-alias two \
  hashicorp/http-echo -text="hello world"
```

### 1.2 启动 Nginx

```bash
docker run --name nginx \
  --network nginx-test -itd \
  -p 80:80 \
  -v ./nginx.conf:/etc/nginx/conf.d/proxy.conf \
  nginx:1.25.1
```

## 二、默认轮询负载均衡

### 2.1 Nginx 配置

```nginx
# 定义上游服务器(默认轮询)
upstream backServer {
    server one:8080;
    server two:5678;
}

server {
    listen      80;
    server_name testnginx.com;

    location / {
        proxy_pass http://backServer;
        index       index.html index.htm;
    }
}
```

### 2.2 配置 hosts 并验证

```bash
# /etc/hosts 添加
127.0.0.1 testnginx.com

# 多次访问,看到轮询不同后端
curl testnginx.com  # {"message":"Hello Gin!"}
curl testnginx.com  # hello world
```

## 三、负载均衡算法

> 默认轮询,以下为常用替代算法。

### 3.1 weight 加权轮询

```nginx
upstream backServer {
    server one:8080 weight=1;
    server two:5678 weight=2;   # two 拿到 2/3 流量
}
```

### 3.2 ip_hash(会话粘性)

> 按客户端 IP 哈希结果分配,同一 IP 固定访问同一后端,可解决 session 共享问题。俗称 IP 绑定。

```nginx
upstream backServer {
    server one:8080;
    server two:5678;
    ip_hash;
}
```

验证:

```bash
# 配置后多次访问,会一直命中同一后端
curl testnginx.com

# 用不同 X-Forwarded-For 验证粘性(测试未生效:ip_hash 默认取 remote_addr,不取 XFF)
curl --header "X-Forwarded-For:192.168.1.1" testnginx.com
curl --header "X-Forwarded-For:192.168.1.2" testnginx.com
curl --header "X-Forwarded-For:192.168.1.5" testnginx.com
```

> **注意**:ip_hash 取的是 TCP 直连 IP(`$remote_addr`),不是 `X-Forwarded-For`。要在反代链路中生效,需配合 `set_real_ip_from` 与 `real_ip_header`。

> **故障行为**:粘性保持在 one 时,one 宕机会自动转发到 two;one 恢复后会重新转发回 one。

### 3.3 其他算法

| 算法 | 说明 | 来源 |
|------|------|------|
| fair | 按后端响应时间智能分配,响应短的优先 | 第三方 `upstream_fair` 模块 |
| url_hash | 按 URL 哈希分配,提高后端缓存命中 | 第三方 `nginx_http_hash` 模块 |

## 四、故障转移

> 当上游服务器故障或超时,自动切换到下一台。

### 4.1 配置超时与切换

```nginx
upstream backServer {
    server one:8080;
    server two:5678;
}

server {
    listen      80;
    server_name testnginx.com;

    location / {
        proxy_pass http://backServer;

        # nginx 与后端的连接超时(发起握手等候响应)
        proxy_connect_timeout 1s;
        # nginx 发送请求给后端的超时
        proxy_send_timeout    1s;
        # nginx 读取后端响应的超时
        proxy_read_timeout     1s;

        index index.html index.htm;
    }
}
```

### 4.2 故障验证

```bash
# 启动后关闭 one
docker stop one

# 继续访问,流量切到 two
curl testnginx.com
```

> 即使不显式配置故障转移,Nginx 也会在默认超时后切换;配置超时参数可让切换更快。
